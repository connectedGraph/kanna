# 汉化实现规范（给改代码的人 / agent）

骨架已完成，下面是**改每一个组件时必须遵守的规则**。

## 一句话

英文原文就是 key：组件里写 `t("New Chat")`，中文表里写 `"New Chat": "新建会话"`。

## 改组件

```tsx
import { useT } from "../../i18n/useT"

export function Foo() {
  const t = useT()
  ...
  <span>{t("New Chat")}</span>
  <Input placeholder={t("Search chats")} />
  <Button title={t("Resize sidebar")}>…</Button>
}
```

规则：

1. **key 就是英文原文，一字不改**：包括 `…`、大小写、标点。写错了中文表就匹配不上，
   界面上会退回英文（不会崩，但等于没翻）。
2. **带变量的字符串**用 `{name}` 占位：
   ```tsx
   {t("Update to {version}", { version: latest })}
   ```
   对应的中文 `"Update to {version}": "更新到 {version}"`。
3. **不要给 `<Trans>` 式富文本加翻译**。若一句里嵌了 `<code>`、`<Link>`，
   把整句拆成「前缀 / 中间 / 后缀」几段分别 `t()`，保持词序可换的语言也能勉强读。
   拆分后每段仍是完整、独立的 key。
4. **属性也要翻**：`title`、`aria-label`、`placeholder`、`alt`、`label` 一律翻。
   `aria-label` 和 `title` 同文时各写一遍（不要为了省事复用常量，读代码时看不见）。
5. **不要翻**：CSS 类名、`data-*`、测试 ID、命令、路径、模型 ID、品牌名（见 `GLOSSARY.md`）。
6. **字符串常量提到组件外的**（如 `themeOptions`、菜单项数组）：
   改成一个工厂函数或在渲染处翻译正确的位置。
   - 若是渲染时求值的常量数组 → 把它挪进组件体内，或存 key、渲染时 `t(option.label)`。
   - 若是纯模块（`command-palette/*.ts`，不能调 hook）→ 用 `translatorFor(locale)`。
7. **服务端下发文案不翻**（`ws-router.ts` 的 `error`、`diff-store.ts` 的 throw）。
   首版范围明确排除，别顺手改。
8. **`null` / 条件文案**照常处理，例如
   `{isLoading ? t("Checking…") : t("Check for updates")}`。

## 中文表

只往**自己负责的分区**里加，key 不能跨分区重复（`catalog.test.ts` 会拦）。

```ts
// src/shared/i18n/catalog/navigation.ts
export const navigation: Messages = {
  "New Chat": "新建会话",
  "Terminal": "终端",
}
```

- 值不能等于 key（会被测试拦下）。
- 顺序不要求，但同一文件内按英文原文大致分组，便于回查。
- 中文用全角标点，省略号 `…`，中英之间不加空格。

## 自检

```bash
export PATH="$HOME/.bun/bin:$PATH"
cd ~/workspace/categories/artifacts/kanna-i18n/src
npx tsc --noEmit                            # 类型
bun test src/shared/i18n                    # 词表一致性
bun test <你改的组件对应的测试>              # 如果有
```

`bun run check` 会跑全量构建（约 20 秒），收尾时跑一次。

## 边界

- **不要改** `src/client/i18n/`、`src/shared/i18n/index.ts`、`zh-CN.ts` 的汇总结构、
  `docs/GLOSSARY.md` 的核心词表（要加词就加到「核心词」表尾并保持风格）。
- **不要动**别的地方负责的文件：并行改同一文件必然冲突。
- 改动范围之外的 bug 记下来报告，不要顺手修。
